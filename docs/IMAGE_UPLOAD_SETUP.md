11月4日修改云存储权限时，控制台提示“套餐属于免费期，无法进行此操作”；当时测试也确认客户端仍可直接上传。用户已选择暂不升级。11月5日没有得到套餐或权限已变化的证据，自动化工具只能查询文件，不能核实套餐或设置存储规则。

问题属于当前环境权限与上传功能尚未接通，与Ubuntu或图片放置目录无关。昵称和建队不依赖图片上传。

## 配置与开发顺序

1. 微信开发者工具 → 云开发 → 确认环境ID → 云存储 → 权限设置。目标是“仅管理员可读写”，自定义规则为 `{"read":false,"write":false}`。这是云存储设置，与各数据库集合的权限独立。
2. 如果仍提示免费期不可操作，需由环境拥有者在控制台确认可用套餐、费用及生效方式，选择支持该权限配置的方案。具体套餐名称和价格以当时控制台为准；本次未购买、升级或改变计费设置。
3. 保存后实测：客户端直接上传/读取被拒绝，云函数可以写入并签发临时读取链接。测试文件用独立路径并及时清理。仅看到控制台“已保存”不能代替验证。
4. 个人头像：在 `userProfile` 云函数配置环境变量 `USER_PROFILE_AVATAR_ENABLED=true`，保留其他环境变量并重新部署。它不是前端 `VITE_` 变量。服务端使用可信微信身份，校验PNG/JPEG真实内容、大小及尺寸，客户端先压缩；目前限制为256KiB、边长2048和总像素400万。失败不覆盖旧头像。
5. 球队队徽：新增仅领队可用的上传操作；从绑定取得球队ID并确认仍处于active状态，禁止传入任意队伍/文件地址。复用图片校验规范，将文件写到专属球队路径，事务更新队徽及版本；解散或版本冲突时不能更新旧队。后台和小程序取得短期图片链接，过期后重新获取；处理替换后旧文件清理。该项尚未实现。
6. 验证个人头像选图/保存/重进、队徽保存与后台同步、非领队拒绝、非法或超大图片、取消选图、断网、链接过期、替换和解散并发。使用当前可用的iPhone实测并记录设备版本；Android仍待设备验证。

个人头像和队徽分别记录开发、云端验证、真机验证状态；配置未完成前保持默认图案。无需自行配置公网图片服务器，也无需把图片或临时链接提交到Git。
