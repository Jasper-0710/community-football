## 入口与行为

- 微信小程序：个人中心 → 我的报名 → 查看报名与材料 → 历史报名材料 → 查看历史材料。
- 后台：报名审核 → 选择报名记录 → 历史报名材料 → 查看历史材料。
- 当前附件仍在原材料区，历史区只展示曾绑定这条报名、现在已被替换的最终附件。撤销、截止和赛事隐藏后仍可授权查看；这些状态不开放新的修改权限。
- 默认折叠，展开后分页读取，每页最多检查20条登记。登记中包含当前附件时会跳过；若本批没有历史附件但仍有游标，可继续加载。
- 历史区只供查阅，不作为本次审核材料，不提供恢复、删除或重新提交旧材料的按钮，也不冒充完整的历次提交批次。
- 文件格式、大小、上传登记时间和首次提交时间可见。上传时间来自原上传会话的 `createdAt`，不是推算的上传完成时间。旧记录缺少首次提交时间时明确提示未记录；不改写或回填历史。

## 接口和权限

两个函数新增同名只读动作 `registrations.historyFiles`，参数为 `id`、`expectedVersion`，可选 `cursor`。返回报名ID、版本、脱敏文件列表和下一页游标，不返回用户ID、云文件ID、分片、存储路径或临时链接。

`teamManagement` 先验证可信微信身份和报名所有权；`adminAuth` 先验证管理员会话。分页只查询绑定该报名的文件，并复核文件的用户、赛事和报名归属。每页前后检查报名版本，发生提交、审核或撤销时拒绝混读，界面清空旧列表并要求重新读取报名。

`registrations.fileLink` 沿用原授权和300秒签链机制，增加历史文件查找。只有同用户、同赛事、同报名的 `ready` 文件可以签链；未提交草稿、他人文件、其他报名文件、已删除或未完成文件均拒绝。材料开关关闭时仍不签发下载链接。历史元数据可以只读查看。

首次绑定新文件时，在原报名事务内写 `registrationFiles.firstSubmittedAt`，重试、再次使用旧文件或再次提交不覆盖首次时间。已存在的绑定没有时间字段时保持缺失。正常清理继续保留所有已绑定的最终材料，不改变已有保留规则。

共享读取逻辑为 `registration-attachments.js`，由 `scripts/sync-registration-model.mjs` 同步到两个函数。两端共用分页状态逻辑；切换账号、报名、版本或离开页面时清空私有状态，忽略旧请求的晚到响应。
