# D06 赛程与对阵

更新日期：2026-11-11。当前完成本地赛程基础功能与隔离浏览器回归，客户云端尚未部署、尚未验收。

## 已实现

- 后台按赛事新增和编辑比赛，维护阶段、轮次、分组、签位、双方、北京时间、场地及延期状态。
- 确定的参赛球队只从本赛事报名已通过的有效球队中选择；服务端再次检查审核状态。没有确定双方时可先保存待定对阵。
- 淘汰赛从已保存的前序比赛中选择晋级来源，不必输入数据库标识。来源必须属于同一赛事，比赛阶段及开赛时间须早于后续比赛；禁止引用自身、重复来源及同一方同时填写球队和来源。
- 编辑已被后轮引用的比赛时，拒绝破坏晋级时间或阶段顺序的改动。赛事日期范围按北京时间校验。
- 比赛写入、关联球队版本递增和赛事排赛版本递增在同一事务内完成，与球队解散及并行改动形成冲突检查。创建请求可重复提交，编辑检查预期版本，失败时不覆盖已有数据。
- 小程序读取公开赛事的完整赛程；默认显示全部日期，支持日期、球队、状态组合筛选、定位今天及清除筛选。球队筛选可查看该队全部日期的比赛。
- 北京时间凌晨比赛归入正确日期。刷新保留当前赛事及筛选；读取失败清空旧赛程并提供重试。赛事切换或页面退出后，迟到请求不能覆盖新状态；自动翻页检查重复游标和跨赛事数据。
- 390px/320px 窄屏布局已验证，日期保持单行并支持横向滚动。

## 接口与数据

`adminAuth` 新增 `matches.js`，通过 `index.js` 路由。公开操作为 `matches.listPublic` / `matches.getPublic`；管理操作为 `matches.listAdmin` / `matches.create` / `matches.update`，需要既有管理员会话。公开响应不包含管理版本、创建指纹、领队联系方式或报名材料。

列表按比赛 ID 稳定分页，每页最多 20 条；前台读取全部分页后按开赛时间排序。公开查询要求赛事开启展示，仅返回当前支持的已排赛或延期状态。比赛阶段为小组、八强、半决赛、决赛；比分及比赛事件不在本轮写入。

服务端事务读取相关赛事、球队、报名和来源比赛。关联查询与写入通过赛事的 `scheduleMutationVersion` 串行化；引用球队同时递增球队 `version`，遵守 `TEAMS_DEVELOPMENT.md` 的关联保护契约。后续赛果写入也需保留此契约。
