更新：2026-11-18。代码、本地回归及**客户userProfile部署、真实云端非空接口闭环和模拟器重新进入展示已通过**。原收藏已恢复；真实第二微信账号、跨设备、原生退出重登/游客合并点击及手机验收仍单列。

## 功能入口与行为

- 我的 → 我的主队 → 发现球队；或赛事 → 参赛球队。按球队名或地区搜索，进入真实球队主页点击“关注这支球队”。真实比赛、全局搜索中的球队入口同样可进入。
- 微信登录成功后自动读取当前账号的云端收藏；重新登录、另一个设备登录、回到前台及个人中心重新进入时读取最新数据，也可手动“重新同步收藏”。
- 游客可以关注真实球队，保存在按环境及接口隔离的本机游客记录中。登录不会自动搬运记录；点击“合并游客收藏到当前账号”才添加到云端，完整成功后清除游客记录。可单独移除游客记录；合并失败不丢记录，也不部分合并。云端成功、本机清理失败时明确提示，重复合并不重复添加。
- 真实球队收藏与演示收藏独立展示；旧演示缓存只保留在游客演示区。演示收藏按本机确认账号分开，演示ID不能进入真实收藏接口。
- 已隐藏、解散、删除或失去公开参赛资格的球队显示“球队暂不可用”，不返回其名称、地区、联系人或名单，仍可取消关注。网络故障不会冒充球队下架或云端空列表。
- 上限50支真实球队。保存期间禁用重复点击，操作失败不提前修改关注状态。网络结果不确定或版本冲突时先重新同步，再操作。

## 接口与存储

复用 `userProfile`，新增 `favorites.get` / `favorites.set` / `favorites.merge` 三个动作。保留既有登录、昵称、头像及部署环境变量，不新增集合、依赖、索引或配置开关。

请求中的 `expectedOwner` 是当前云端确认资料ID的前置条件，不能授予权限；真正身份只来自 `cloud.getWXContext()`，验证APPID和OPENID及私有 `users` 文档归属。微信附加 `userInfo`、`tcbContext` 完全忽略。禁止客户端指定用户、角色、环境及任意修改字段。

私有 `users/<sha256(APPID:OPENID)>` 增加 `favorites: {version,teamIds,updatedAt}`。事务只更新这个字段，保留昵称、头像、角色及报名业务数据；没有旧字段时读作空列表，读取不主动写入。`users`客户端规则继续 `{"read":false,"write":false}`。

`favorites.set` 提交明确的 `favorite: boolean`、真实 `teamId` 及 `expectedVersion`；合并提交去重后的 `teamIds` 与版本。新增收藏必须有已审核报名且赛事公开，写事务中顺序复核球队、报名及赛事，复用同事务内的重复读取。取消不可用球队无需重新公开。版本冲突拒绝覆盖；目标状态已经满足时不增版本。返回当前账号完整收藏和最小公开球队摘要；不返回OPENID或其他用户数据。

查询报名与赛事按内置 `_id` 索引显式翻页，超过2000条的集合安全报错，不悄悄截断。收藏最多50条；更大规模目录需要后续替换扫描方案并做客户环境性能验收。

账号云端收藏不写本机缓存。账号切换立即清空旧列表，旧登录周期的异步结果不能恢复旧数据或修改新账号加载状态；独立身份监听持续到应用生命周期结束。本机游客使用 `community-football.favorites.v1:` 隔离键；演示键为 `community-football.demo-favorites.v1:`。本机数据从不作为云端授权来源。
