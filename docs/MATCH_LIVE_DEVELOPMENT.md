## 入口与功能

- 后台左侧「图文直播」→选择赛事和比赛→「发布新动态」。可填写最多1000字、0–150分钟（可留空）及最多4张图片，每图可填写100字说明、调整顺序。文字与图片至少提供一项。
- 图片支持本机JPG/PNG上传及已有HTTPS地址。单图最多2MiB、最长边4096、800万像素；64KiB分片、SHA-256、完整解码及上传中断后重试。上传未完成时禁止发布、切换比赛和图片排序，保留候选图供重试/取消。
- 已发布内容支持更正和软删除。更正显示标记，保留首次发布时间及列表顺序；删除需输入「删除」确认。保存结果不确定、版本冲突或图片签名失败时，先「重新读取直播」确认实际结果。
- 客户端「赛事→真实比赛详情→图文直播」。最新内容在前，每页20条，可加载更早动态；前台每15秒更新，也可手动刷新。离页/切换标签/进入后台停止轮询，回到前台恢复；查看更早动态时暂停自动刷新，手动刷新返回最新内容。
- 读取失败保留上次确认的内容并提示重试，首次空列表有明确空态；赛事隐藏后清空旧内容并显示不可访问。图片失败有占位，可刷新链接后重试；图片可预览。

图文内容独立于比分、比赛事件和榜单；发布直播不会写入比赛赛果。演示比赛不显示伪造的直播，视频推流不在本功能范围内。

## 数据、权限与接口

复用 `adminAuth`、当前HTTPS网关和管理员会话。新增集合 `matchLiveEntries`、`matchLiveImages`，均须设置客户端规则 `{"read":false,"write":false}`。公开内容只通过受控接口投影，不直接开放集合或存储。

| action | 权限与参数 |
| --- | --- |
| `live.listPublic` | 公开；`matchId`、可选`cursor`，仅允许真实公开赛事下的有效比赛 |
| `live.listAdmin` | 管理员；`matchId`、可选`cursor` |
| `live.publish` | 管理员；`matchId`、32位十六进制`requestId`、`form` |
| `live.correct` | 管理员；`matchId`、`id`、`expectedVersion`、`requestId`、`form` |
| `live.delete` | 管理员；`matchId`、`id`、`expectedVersion`、`requestId` |
| `live.images.config/start/chunk/finish/get/cleanup` | 管理员；复用图片生命周期，归属字段为`entryId` |

直播ID为 `l_<32hex>`，图片ID为 `li_<32hex>`；仅公开列表为匿名白名单。公开响应不含版本、请求指纹、图片登记ID、文件ID和管理员身份。上传图只持久化归属ID与说明，读取时生成短期链接；已有外部HTTPS图片地址按地址保存，其可用性由外部提供方决定。

发布用稳定请求ID和指纹防止重复创建；更正/删除在事务中检查当前版本并保留最近20次请求以处理重试。图片归属和内容引用同事务提交，不能跨直播绑定，也不能使用新闻图片ID。公开读取在签发图片链接前后复核赛事可见性。版本冲突拒绝覆盖；写入已提交而签名失败返回 `WRITE_COMMITTED`，要求重读而非再次创建。

云存储路径为 `match-live/staging/...` 和 `match-live/files/...`，与新闻图片隔离。已发布引用受保护；未使用、替换或删除后的图片保留24小时。后台「直播图片维护」默认只检查，确认后按页执行清理，事务复核引用、路径和租约；支持下一页及失败后重试，没有定时清理任务。

每场直播以 `_id` 显式100条分页读取，再按发布时间与ID倒序返回20条；累计含软删除记录超过2000条时明确失败，不返回被截断的成功列表。部署时建议建立 `matchId`升序＋`_id`升序索引，并通过客户实际查询核验。高频/大规模发布的索引查询与吞吐测试仍待专项。
