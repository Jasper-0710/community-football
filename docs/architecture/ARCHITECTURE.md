# 前端原型架构

## 1. 上下文与边界

使用者为社区观众、球员和球队支持者。本期验证页面外观与赛事浏览路径，无服务端、管理员界面、微信身份授权或真实网络数据。设备存储仅保存关注球队 ID。统计 SDK 显式关闭。

主要验收路径：
- 首页 → 比赛卡片 → 比赛详情 → 球队主页。
- 赛事 → 日期/状态/球队筛选 → 空状态与重置。
- 赛事 → 淘汰赛签位 → 未定/已结束比赛。
- 新闻分类 → 文章；关注 → 我的主队。

## 2. 运行组件

| 模块 | 责任 |
| --- | --- |
| pages / views | 页面状态、路由、筛选和展示，不维护独立比分副本 |
| components | 共享比赛、榜单、签位、导航与搜索交互 |
| composables/useTournament | 单次加载、缓存、加载失败与重试 |
| data/repository | 数据来源选择。当前返回独立的本地演示快照 |
| domain | 无框架依赖的数据类型、积分、球员统计和递归晋级纯函数 |
| composables/useFavorites | 设备存储适配，不模拟账号同步 |

## 3. 接口与数据所有权

`TournamentRepository.load(): Promise<Tournament>` 是数据替换入口。`Tournament` 包含球队、球员、比赛与文章，类型见 `src/domain/types.ts`。

权威演示事实只在 `src/data/mock.ts` 存放一次。`resolvedMatches` 根据已结束比赛推导后续签位。积分只计算已结束的小组赛，球员榜计算所有已结束比赛的进球事件。未开赛比分为 null。

生产后端需要负责事实校验、授权、数据更正与赛事规则；前端的演示计算不是生产权限边界。未来可以由适配器把后端权威榜单映射到 UI，不必在页面内散布 HTTP 格式。

## 4. 风险与保留项

- H5 预览、微信编译和微信真机验收是三个不同层次。本轮不把编译成功视为真机通过。
- 同分、点球、弃赛、延期、纪律处罚、进球回滚应由正式业务规则定义。当前只验证有限的演示规则。
- 当前数组适合原型数据量，生产新闻和赛程需分页/窗口化与缓存策略。
- 无登录/支付/订阅消息，避免原型假成功。
- 照片为通用视觉素材，正式运营前替换。

## 5. 验证

领域单测检查积分、晋级、事件/比分一致性、空比分、组合筛选、排序与克隆边界。浏览器测试验证实际路由/交互、关注持久化、无效 ID 和多尺寸无整页横向溢出。构建同时执行 H5 与 mp-weixin。

架构图见 `diagram.mmd`，选型见 ADR 0001。
