# 单场历史赛果恢复

更新日期：2026-11-23，Markdown v2.46。对应上线前工作包D（#20、#27；D07/D08）。adminAuth客户部署及模拟非空恢复技术验收已通过；后台按用户确认更新现有本机入口，正式托管与微信真机等单列。与D13整库恢复分别跟踪。

## 操作入口

1. 后台左侧“榜单与晋级 → 赛果与事件”，选择赛事，在某场比赛点击“更正历史”。
2. 历史列表显示比赛版本、时间、原因；可展开比分、点球、进球/乌龙、红黄牌、换人和六项技术统计。对早于当前比赛版本且包含赛果的记录，点击“预览恢复 vN”。撤销记录不作为恢复来源。
3. 预览并排展示当前与所选历史赛果，手机改为上下展示。保留历史事件中的球员姓名和号码；后来改名、换号或移出名单均不改写原记录。
4. 填写恢复原因并勾选核对，再点击“确认恢复历史赛果”。成功会生成当前比赛版本+1的新修订，记录恢复来源、操作者、原因、前后赛果与时间；原历史不覆盖。榜单、晋级、冠军及公开档案沿用同一当前赛果重算，客户端刷新读取。

相同比分可能对应不同进球者/助攻、牌面、换人和统计，必须明确选择历史版本。普通比分更正仍保存本次填写的事件，不根据比分猜测历史。历史进行中版本可恢复状态及分钟，但不计入完赛榜单与晋级。

## 服务与保护

- `standings.history`增加修订ID、历史主客队ID及可选恢复来源，保留20条分页；后台兼容旧响应缺少ID时只查看历史。
- 新增管理员动作`standings.previewRestoreResult`与`standings.restoreResult`。请求指定比赛、目标修订ID/版本及当前比赛/榜单版本；不接受浏览器上传替代事件。服务端通过既有`tx.revision(id)`读取精确数据库记录，校验赛事/比赛归属及早于当前版本。
- 预览不写比赛/球队/赛事/历史。预览和提交均在榜单事务内解析当前参赛方，校验当前报名/球队、历史事件与现赛制，并调用既有赛程和后轮保护；参赛球队变化或主客互换不能恢复。后轮进行中/完赛受影响时，须先撤销相关后轮。
- 预览摘要绑定前后赛果、选定历史和当前版本/球队版本等事实；提交重新校验，预览后有变化即拒绝。单场原子写入比赛、新修订、球队版本和赛事榜单版本，中途存储失败全部回滚。
- 每次恢复使用固定请求ID；相同请求重试只回原修订，不重复写入。同请求改原因/目标/摘要或过期并发请求拒绝。后台收到超时/网络/损坏响应时保留原请求和不可编辑的参数，可“重试确认恢复”；刷新后应先核对最新赛果与历史再决定新操作。
- 保留管理员鉴权、HTTP来源和D13整库恢复互斥。两个动作均不在公开允许列表；预览按管理只读动作分类。公开赛程、榜单和比赛详情不暴露原因、操作者、指纹或恢复来源。

新增`cloudfunctions/adminAuth/result-restore.js`校验历史快照；共享`src/domain/standings.ts`增加恢复预览/回执解析，核对比赛、版本和目标。后台`ResultSnapshot.vue`用于历史详情与恢复对比。复用`resultRevisions`及原私有权限/索引，不新增集合、环境变量或HTTP路由，也无需因D改动publicRead允许动作。
