# D05 球队报名与后台审核

更新：2026-11-10。主要代码及本地验证已有；客户环境集合/权限/索引和后台入口已就绪，私有存储已通过头像技术链路验证，用户头像上传通过。报名材料开关仍关闭；报名函数超时/显式变量、真实材料上传下载、报名写入/审核及iPhone仍待验，过期/孤立附件清理未开发。D05不是已上线或整项已验收。

## 已确认范围与暂定细则

用户确认：报名须提交材料，经后台审核；表单只填写球队名、所属地区、报名项目、领队姓名、联系方式和附件。球队名额、每队人数按赛事配置。截止前允许修改和撤销，截止后锁定，撤销释放名额。

以下按建议做成可调整实现，尚无客户进一步确认：关联领队本人已创建的球队；每队每赛事一条报名；项目由后台配置；附件必传1–5份、每份≤10MB；PDF/JPG/PNG/DOCX/XLSX（旧版DOC/XLS暂不支持）；待审核与已通过占位，驳回与撤销释放；任何资料修改重新审核，驳回原因必填。参赛人数由管理员对照材料核对，不额外要求领队选择球员或填写人数。跨队球员身份识别及跨赛事限制仍待规则和唯一身份字段，未实现自动查重。

## 页面与操作

小程序：赛事详情 → 为我的球队报名 → 填写五个字段并上传材料 → 确认提交。个人中心 → 我的报名，可查看状态、材料、原因及最近20次动态。队名、地区、联系电话从当前球队带出；领队姓名单独填写，不把昵称当真实姓名。表单修改只更新本次报名快照，不改球队档案。

后台：赛事管理 → 编辑赛事 → 配置报名项目、球队上限（留空不限）、每队人数上下限；报名审核 → 选择赛事/状态 → 查看资料并下载材料 → 核对人数后通过，或填写原因驳回。“已通过（参赛名单）”供线下抽签与后续 D06 排赛程使用。记录通过后不提供直接再次审核按钮，领队修改后会重回待审核。

报名状态：待审核 → 已通过/已驳回；截止前，待审核/已通过/已驳回可撤销，已撤销/已驳回可在报名开放时重新提交。截止时刻即锁定领队写入，后台可继续审核。暂停新报名时，已有待审/已通过记录仍可在截止前修改；隐藏赛事停止修改/新报名，已有记录仍可查阅和撤销。后台延长截止时间属于更改赛事安排，需业务负责人知悉。

## 数据与权限

- `registrations`：赛事、球队、可信微信用户所有权，报名表和不可变附件快照，审核结果、版本、最近请求指纹、最近20次动态。软撤销保留历史关联，撤销不解除 D04 的球队解散限制。
- `registrationFiles`：服务端生成的文件ID、所有者、赛事、文件名/大小/类型、分片摘要、状态、有效期、最终云文件引用、绑定的报名ID。两个新增集合必须禁止小程序客户端直接读写。
- `competitions.registrationConfig`：`projects`、`teamLimit`、`minPlayers`、`maxPlayers`；`registrationRulesVersion`独立于报名计数版本；`registrationStats`记录pending/approved/occupied。
- 同一事务提交报名、名额变化、文件绑定及球队version变更，保证最后一个名额不会超售，避免报名与解散并发产生悬空引用。重复请求不重复占位；过期版本要求重新读取。
- 历史赛事无配置时可继续展示与编辑，但拒绝新报名；不默认套用演示人数或额度。管理员不能清空已有占位报名的配置、删除原项目或将名额上限改到已占位数以下。已提交的人数要求保留提交时快照，新修改/新报名使用当前配置。
- 小程序仅通过 `teamManagement` 的可信 WX 上下文访问本人记录；后台 `adminAuth` 的 `registrations.*` 全部验证管理员会话，不加入公开接口白名单。公开页面仅展示赛事配置和合计数量。

已部署并查询核验的4个索引（字段均升序）：`registrations(ownerUserId,_id)`、`registrations(competitionId,_id)`、`registrations(competitionId,status,_id)`、`registrations(teamId)`。已通过真实云端空列表与状态筛选查询；有数据分页与性能仍待后续验证。

## 材料传输与环境配置

材料按192KiB分段通过云函数传输，每次只接受服务端分配的上传会话，不向客户端开放云存储写入权或任何云凭据。每段验证大小及摘要，完成后在服务端检查格式并合并至随机的最终路径。最终对象不向客户端暴露上传入口；报名只接受同用户、同赛事、已完成的文件。链接在 owner/admin 授权之后签发，有效期300秒，不落入数据库的公开投影。Word/Excel目前指DOCX/XLSX；内容识别不是病毒扫描或参赛资料内容审核。

`REGISTRATION_UPLOADS_ENABLED` 是 **云函数环境变量**，须在teamManagement/adminAuth两处设置，默认false。不要加到 `VITE_` 客户端变量中。禁用时阻止上传、新提交及材料链接获取。

启用顺序：

1. 仅在客户环境 `cloud1-d6gzg20x709d7f6c1` 核对 `registrations`、`registrationFiles` 集合（已创建，无需重建），权限均设置为 `{"read":false,"write":false}`，实测客户端直读/直写被拒绝。
2. 更新部署 `teamManagement`、`adminAuth`（远端安装依赖）。部署前运行 `npm run check:registration-contract`；共享状态规则源码在teamManagement，执行 `node scripts/sync-registration-model.mjs` 同步副本到adminAuth。
3. 仅核验客户环境teamManagement执行超时60秒、adminAuth执行超时20秒目标。旧环境曾有控制台60/20秒与工具3/3秒不一致的历史，不将其当作客户环境当前实测结果；userProfile已回读20秒不能代替这两个报名函数的验证。
4. 客户环境私有存储已在11/9头像链路验证，11/10用户头像上传通过，无需重新开通。报名材料仍须独立验证客户端直接访问受限、本人/后台经云函数授权下载可用；原环境免费期限制仅作为历史记录。
5. 私有权限验证后，才启用两个函数的 `REGISTRATION_UPLOADS_ENABLED=true` 并核对最终配置。用不含个人信息的材料验证实际分段上传、文件合并、PDF/图片/Word/Excel下载打开、10MB文件及失败重试。
6. 若微信真机提示下载域名限制，根据实际临时链接的主机名核对小程序downloadFile合法域名；不能从演示域名猜测。iPhone首次文件选择隐私授权、微信聊天文件选择及文档打开需要真机验证。

上传会话24小时有效，每用户最多10个未提交会话；已提交附件释放会话槽位，保留最终文件用于历史查阅。正常完成会删除分片，未绑定材料可通过页面“移除”清理。未完成/过期会话和提交结果不明时留下的孤立对象尚无自动定时清理：上线前须实现按注册表核对的保留/清理任务，避免删掉已绑定附件；不能宣称24小时后物理文件会自动删除。报名动态只保留最近20次，不是全量审计系统。

依赖兼容：当前云函数Node16使用file-type16识别六类材料；已在调用前强制校验对应文件签名，拒绝ASF等非支持输入，避免进入该旧版检测器的已知ASF解析问题。升级云运行时后应升级检测库；相关拒绝用例已加入测试。未对项目全部历史依赖做无关版本升级。
