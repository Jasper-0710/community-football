## 已实现的使用流程

领队从“我的 → 我的球队 → 球队队徽”选择相册图片或拍照。建队成功后再设置队徽，上传失败可独立重试，不会再次创建球队。

入口在微信小程序，需以球队领队账号登录并已创建球队；位于球队资料下方、球员名单上方。编辑球队、编辑球员或确认解散时暂时收起，先保存/取消编辑再查看。后台“球队档案”展示队徽及清理入口。环境未开放时，小程序仍显示灰色“选择队徽”按钮和“尚未开放”说明，保留明确入口。

- JPG/PNG 原图不超过10MiB；本机按比例缩小至最长边目标512像素，必要时继续压缩，最终不超过256KiB。选择后先本地预览，点击“保存队徽”才开始上传和绑定；取消本次修改不改变已保存队徽。
- 64KiB分片，最多4片；网络失败后复用当前上传请求和服务端已收到的分片。上传或合并失败保留原队徽；保存回执不明或版本冲突时先“重新读取队徽”确认结果。
- 支持更换队徽、恢复默认及取消恢复默认。保存后“我的球队”、后台档案和已公开参赛球队详情读取同一保存结果；临时链接失效显示默认图案，并提供重新读取入口。
- 后台档案保持只读；“队徽存储维护”支持先检查、再清理本批、检查下一批。清理保护当前球队和已解散档案引用的最终队徽。

## 数据与接口

新增私有集合 `teamBadges`，主键为 `tb_` 加32位请求ID。记录可信领队ID、原球队ID、图片类型/体积/尺寸/哈希、分片、预登记对象、引用、过期及清理状态。未保存会话和被替换图片保留24小时；对象写入保护期10分钟。元数据按 `_id` 默认索引每次检查20条，不使用定时任务。

`teams` 增加 `badgeId`、`badgeFileId` 和最后队徽提交信息；原有无队徽记录继续显示默认图案。上传完成仅生成候选，`badges.save` 才在同一事务里更新球队版本、最终文件及新旧图片引用。解散保留最终引用；重新建队后旧上传不能附到新球队。球队不保存签名URL。

`teamManagement` 只接收微信可信上下文，以下写入逐次核验本人当前球队绑定及归属，不信任客户端身份或任意存储地址：

| action | 业务输入 | 用途 |
| --- | --- | --- |
| `badges.config` | 无 | 读取开关和体积/分片上限 |
| `badges.start` | teamId、requestId、size、mime | 创建/恢复上传会话 |
| `badges.chunk` | id、index、data | 上传Base64分片，同一分片内容不可变 |
| `badges.finish` | id | 校验分片、实际解码JPG/PNG，生成最终图片 |
| `badges.save` | teamId、id、expectedVersion | 原子绑定队徽；成功请求重试不重复增加版本 |
| `badges.remove` | teamId、expectedVersion | 恢复默认队徽，解除原引用 |

云端拒绝超过256KiB、边长2048像素或总像素400万的图片，并验证完整PNG/JPEG结构和解码结果。文件限定在本环境 `team-badges/staging/<teamId>/<badgeId>/` 和 `team-badges/files/<teamId>/<badgeId>/`；对象在写入前登记，以便响应丢失后仍可核对和清理。

`adminAuth` 新增有效管理员会话接口 `teams.badges.cleanup`，接受 `dryRun` 布尔值和可选 `cursor`。公开球队沿用D09的“展示赛事 + 已通过报名 + 未解散”条件，仅返回 `hasBadge` 和短期HTTPS链接，不返回文件ID、上传登记、领队身份或联系电话。

若开发中的后台曾提示`api.cleanupTeamBadges is not a function`，这是运行中的前端API实例缺少新方法，请先强制刷新后台（macOS：⌘⇧R）。本轮已增加API模块热更新后的整页重载，按现有会话重新向服务端校验后重建实例；本地三组HMR回归覆盖旧实例复现、重载保留登录态和真实清理预览调用。此错误发生在请求前，不是云函数参数错误。实际清理还依赖下列客户部署完成。
