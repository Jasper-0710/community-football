## 运行

跨电脑开发统一建议使用 Node.js 22 及其自带的 npm，版本约定见 `.nvmrc`。已经安装 nvm 的 Linux/macOS 电脑可运行 `nvm install`、`nvm use`；Windows 可直接安装 Node.js 22。

```bash
npm ci
npm run cloud:setup
npm run cloud:check
npm run dev:h5
```

打开 `http://127.0.0.1:5173/`。按浏览器开发者工具的设备切换按钮即可预览手机布局。

也提供了本地运行入口：

```bash
./scripts/run.sh run dev:h5
```

`run.sh` 优先使用系统 npm，仅当它不存在时尝试本机已有的 Codex Node 运行时和 `.tools` 下的项目内 npm。这是开发便利脚本，**运行与发布代码不依赖 Codex**。其他机器正常安装 Node/npm 即可。

首次克隆或从其他电脑同步后，在项目根目录执行 `npm ci`，按锁文件安装当前系统的依赖。不要跨电脑复制 `node_modules`；macOS、Linux 和 Windows 使用不同的 esbuild/Rollup 原生文件。Git 初始化、上传和日常同步流程见 [跨电脑开发说明](docs/DEVELOPMENT.md)。

项目通过 npm workspaces 同时安装 `cloudfunctions/*` 的运行依赖，供本地云函数测试使用。云函数部署时选择“云端安装依赖”，不会将本机的 `node_modules` 当作跨平台部署包。

## 已有功能与联动

- **首页和公开档案**：从云端读取赛事、比赛日、球队／球员及资讯；球队按赛事查看战绩、进失球、赛程，球员查看有效比赛事件与统计；隐藏、更正、撤销后同步。
- **赛事与球队报名**：创建编辑赛事、独立展示／报名开关；领队建队和名单维护、上传报名材料、提交／修改／撤销，管理端审核并按当前赛事要求校验。
- **赛程、赛果和晋级**：实际抽签来源与签位、筛选／详情、比分与事件／统计、历史修订恢复；积分、射手、助攻、冠军及真实来源对阵图联动。四队小组和完整八强已有客户云端技术验收，正式赛制与剩余专项仍需核对。
- **资讯和搜索**：图文草稿／发布／置顶／更正／撤回／删除、图片管理，球队／球员／比赛／文章四类搜索及设备搜索历史。实际热度统计和超过当前扫描范围的搜索方案另列。
- **个人中心、外观和收藏**：微信登录／昵称／头像、我的球队／报名，平台默认主题与六个导航、个人本机覆盖；已登录收藏已有云端同步，游客合并／原生重登／多账号设备等剩余场景待验。
- **直播、评分和评选**：比赛图文动态、图片、分页和更新；评分、评论审核及本场MVP／最佳阵容已有客户云端基础闭环，原生参与和真机等继续待验。
- **备份与故障恢复**：有边界的同环境备份／恢复／回退，主服务→云端公开备用→本机快照→重连已有非空技术证据；离线只读，运行边界和正式托管来源继续验证。
- **社区与投保专栏（F）**：客户端和函数已部署，图片配置／上传闭环、真实外跳及真机未收口；当前关闭，不显示虚假可用入口。

## 构建微信小程序

```bash
npm ci # 首次导入或依赖变化时执行
npm run build:mp-weixin
# 或开发模式：
npm run dev:mp-weixin
```

1. 安装微信开发者工具。
2. 检查 `src/manifest.json` 的 `mp-weixin.appid`，当前已经配置 AppID。使用有该小程序开发权限的微信账号；如需更换 AppID，修改源配置后重新构建。AppSecret 和上传私钥不属于此配置。
3. 编译后导入项目根目录（包含 `package.json` 和自动生成的 `project.config.json`）。构建命令会将小程序目录设为 `dist/build/mp-weixin`，开发模式设为 `dist/dev/mp-weixin`，同时关联根目录的 `cloudfunctions/`。
4. 在开发者工具中检查滚动、导航、胶囊避让、底部安全区，并进行手机真机预览。

**编译产物不代表已通过微信原生控件或真机验收。** 分项技术证据、用户确认和剩余范围见 [验收流程](docs/VERIFICATION.md)。0.1.1上传／预览是既有部署结果，不代表已提审或正式发布。

现有客户环境已就绪。新电脑先执行 `npm run cloud:setup`、`npm run cloud:check`，按[云开发配置](docs/CLOUD_DEVELOPMENT.md)核对生成配置；不重复初始化管理员、集合或部署已通过的函数。环境变更后重新构建，真实接口错误不能用模拟用户或比分代替。

## 代码结构

```text
src/
  components/          比赛卡片、对阵图、积分表、页面框架、搜索
  views/               首页 / 赛事 / 动态 / 数据 / 我的
  pages/               根页、赛事/报名/球队/球员/比赛/文章等页面
  domain/              数据类型、积分与晋级等纯函数
  data/                单一演示数据集与可替换的数据源
  composables/         登录态复用、加载状态和业务数据
  styles/              共享设计变量、响应式布局
  static/              本地照片、原创队徽和图标
  services/            微信云调用、HTTPS公开读取及各业务服务
admin/                 独立网页管理后台及各赛事运营模块
cloudfunctions/        healthCheck、userProfile、adminAuth、teamManagement、publicRead
```

### 业务数据边界

正式页面通过 `src/services/` 和共享数据结构读取权威业务数据，云函数校验身份、权限、版本及赛事规则，比赛和榜单按有效赛果联动。`src/data/` 中的演示资料和本地隔离测试不能代替客户环境验收。生产队数、积分／并列与晋级规则须按客户确认口径配置。
